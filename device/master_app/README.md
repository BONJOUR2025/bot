# Приложение «BONJOUR Мастер»

Android-приложение для **личных телефонов мастеров**: заработок по сканам,
работы в процессе, запрос аванса с лимитом, история, отгулы, профиль.

## Как устроено

Это оболочка над кабинетом сотрудника на `https://app.bonjour.pw` — один
экран с WebView, стартовая страница `/employee/earnings`. Своих экранов у
приложения нет **намеренно**: всё, что видит мастер, — веб-кабинет
(`admin_frontend/src/pages/employee/EmployeeMaster*.jsx`), поэтому новый
раздел или исправление приезжают на телефоны с обычным деплоем сервера. APK
пересобирать нужно, только когда меняется сама оболочка.

Почему нативный WebView, а не Capacitor, как у iOS-обёртки: оболочке нужны
три вещи — показать сайт, выбрать фото для профиля и не выпускать мастера на
чужие адреса. Capacitor добавил бы в сборку Node, `npx cap add android` и
синхронизацию платформы ради того, что укладывается в один `MainActivity.kt`
и собирается тем же Gradle, что и агент MDM.

Данные и правила — те же, что у раздела мастера в Telegram-боте
(`app/services/master_bot_service.py`): мастер опознаётся по коду Агбиса из
карточки, видит только свои сканы, отчёт берётся из прогретого кэша.
Разделы кабинета у мастера свои (`is_master` в `/api/auth/me`): «Зарплата» и
«График» читают Excel админов, где мастеров нет, поэтому вместо них —
«Заработок» и «В работе».

## Вход

По логину и паролю из панели: «Настройки → Доступы → пользователь», поле
«сотрудник» — карточка мастера. Токен мастера без прав в панели живёт 30
дней, а не 12 часов (`MASTER_TOKEN_TTL_SECONDS`): иначе вводить пароль
пришлось бы дважды в день, и приложением просто перестали бы пользоваться.
Срок считается при каждой проверке: перестал быть мастером — снова 12 часов.

## Раздача

Ссылка для мастера: **https://app.bonjour.pw/api/master-app/** — страница с
кнопкой скачивания и тремя шагами установки. Сам файл —
`/api/master-app/bonjour-master.apk`, версия — `/api/master-app/info`. Всё без
авторизации: секретов в APK нет, а в кабинет пускают только по паролю.

На сервере файл лежит в корне рабочей директории (`master_app.apk`), а не в
`app/` — деплой зеркалит `app/` через `robocopy /MIR` и снёс бы его.

## Сборка

Локально собрать нечем (нет JDK и Android SDK). APK собирает GitHub Actions
(`.github/workflows/master-app.yml`) на каждый пуш в `device/master_app/` и
сам кладёт его на сервер (`POST /api/master-app/upload`, токен
`MDM_UPLOAD_TOKEN`). Артефакт сборки `bonjour-master-app` остаётся запасным
путём.

**Перед выпуском новой версии поднимите `appVersionCode`** в
`app/build.gradle.kts` — APK с тем же кодом Android поверх установленного не
поставит.

Подписывается тем же ключом, что агент MDM (секреты `MDM_KEYSTORE_B64` и
`MDM_KEYSTORE_PASSWORD`, алиас `mdm`). Отдельный ключ потребовал бы завести
новые секреты руками, а смешения прав тут нет: права владельца устройства
принадлежат самому агенту, а не ключу, и в APK уходит только публичный
сертификат. **Ключ менять нельзя**: обновление с другой подписью поверх
установленного приложения не встанет, каждому мастеру придётся удалять и
ставить заново.

## Что внутри WebView не работает

- **Push-уведомления браузера** — WebView не поддерживает Push API. Кабинет
  узнаёт приложение по метке `BonjourMasterApp` в User-Agent и прячет
  переключатель, чтобы он не делал вид, что работает.
- **Скачивание файлов** (выгрузка истории) — по той же метке кнопка скрыта.

## Установка на телефон

Мастер открывает ссылку, скачивает файл и открывает его. Android попросит
разрешить установку из этого источника (браузера), Play Защита может
предупредить о неизвестном приложении — «Подробнее» → «Всё равно
установить». Минимальная версия Android — 7.0.
