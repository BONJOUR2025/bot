# Агент наблюдения для салонных компьютеров

Маленькая служба, которая раз в несколько минут рассказывает серверу, как дела
у компьютера: жив ли он, сколько места на дисках, запущены ли Firebird и Agbis,
не ждёт ли Windows перезагрузки. Панель показывает это списком, сторож пишет в
Telegram, когда что-то отвалилось.

## Он ничего не делает на компьютере — и это намеренно

В агенте **нет кода, исполняющего команды**. Не «пока нет», а по конструкции:
сервер не может ни запустить программу, ни перезагрузить машину, ни положить
файл. Причина простая — на этих компьютерах касса, Firebird с продажами и
Agbis. Ошибочная команда на телефоне стоит перезагрузки, на кассовом ПК —
рабочего дня салона, а захваченный сервер стоил бы куда дороже.

Цена решения: обновлять агента приходится тем же удалённым доступом, которым
его ставили. На парке в несколько машин это дешевле, чем держать на кассе
исполнителя произвольных команд.

Если однажды понадобится что-то уметь делать, это будет **белый список
конкретных действий** (перезапустить зависший Agbis, показать сообщение), а не
«выполнить строку», которую пришлёт сервер.

## Чем отличается от MDM телефонов

| | Телефоны (Android) | Компьютеры (Windows) |
|---|---|---|
| Что умеет | ~30 команд, политика, киоск | только отчёт о себе |
| Связь | длинный опрос, отклик 0,5 с | отчёт раз в 5 минут |
| Неудаляемость | Device Owner, только сброс | нет, снимается администратором |

Аналога Device Owner на Windows не существует: агент с правами администратора
снимается за минуту. Если задача — чтобы сотрудник не мог его отключить, она
решается не агентом, а тем, что у сотрудника нет прав администратора.

## Установка

Нужен Python 3.11+ и две библиотеки:

    pip install psutil requests

Положить рядом `agent.py` и `agent.ini`:

    [agent]
    server = https://app.bonjour.pw
    enroll_key = <WORKSTATION_ENROLL_KEY из config.json сервера>

Проверить руками — агент напечатает, что зарегистрировался, и пойдёт слать
отчёты:

    python agent.py

Дальше поставить службой, чтобы работал без входа в систему. Проще всего
через штатный планировщик, задача «при загрузке компьютера», от SYSTEM:

    schtasks /create /tn "BonjourAgent" /tr "pythonw C:\bonjour-agent\agent.py" ^
             /sc onstart /ru SYSTEM /rl HIGHEST /f

`pythonw`, а не `python` — иначе на кассе будет висеть чёрное окно консоли.

Токен агент получает при первой регистрации и хранит в `state.json` рядом с
собой; ключ регистрации после этого больше не нужен, но пусть лежит — по нему
агент перерегистрируется, если карточку удалят из панели.

## Что настраивается с сервера

В `config.json` продакшн-директории:

- `WORKSTATION_ENROLL_KEY` — ключ регистрации;
- `WORKSTATION_CHECKIN_SECONDS` — как часто присылать отчёт (60…3600, по
  умолчанию 300);
- `WORKSTATION_WATCH_PROCESSES` — список процессов, о которых докладывать.
  Задаётся списком, чтобы добавить наблюдение за новой программой можно было
  без обхода машин. По умолчанию `fbserver.exe`, `fb_inet_server.exe`,
  `Agbis.exe`.

Читаются живьём: правка `config.json` действует без перезапуска сервера, а
агенты подхватят новые значения ближайшим отчётом.

## Когда тревожит

- **мало места** — меньше 10% или меньше 5 ГБ на разделе. Главный повод: при
  переполнении встаёт Firebird, а вместе с ним продажи салона;
- **не запущен** один из наблюдаемых процессов;
- **ждёт перезагрузки** после обновлений Windows;
- **молчит** — отчётов нет дольше положенного (считает сторож на сервере, а не
  агент: выключенный компьютер о себе не расскажет).
