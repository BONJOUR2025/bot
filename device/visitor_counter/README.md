# Счётчик посетителей (ESP8266 + локальный релей)

Два файла, которые реально крутятся вне этого backend-приложения:

- `main.py` — заливается на саму плату ESP8266 (MicroPython). Читает два ИК-датчика
  на разрыв луча и по порядку срабатывания определяет направление прохода.
- `relay.py` — лёгкий Flask-сервер, запускается на ПК в той же локальной сети, что и
  плата. Плата по Wi-Fi бьёт сюда простым `GET /event?direction=in|out`, а relay уже
  пересылает событие в облако на `/api/visitor-events/ingest` с API-ключом.

Почему два хопа, а не плата → облако напрямую: ESP8266 плохо работает с TLS
(HTTPS) из-за ограничений по памяти, поэтому она ходит по HTTP в локальной сети на
relay, а уже relay (на нормальном ПК) делает HTTPS-запрос в облако.

## Настройка

В `main.py` заполните:
- `WIFI_SSID` / `WIFI_PASSWORD` — данные вашей Wi-Fi сети.
- `RELAY_HOST` — IP адрес ПК с запущенным `relay.py` в той же сети.

В `relay.py` заполните:
- `API_KEY` — ключ с вкладки «Счётчик посетителей → Подключение устройства» в админке.
- `SALON_CODE` — код салона (тот же, что в разделе «Салоны»), к которому привязана эта плата.

**Не коммитьте реальные Wi-Fi пароль и API-ключ в репозиторий** — впишите их
прямо на плате/сервере при разворачивании, в коде оставлены только плейсхолдеры.

## Диагностика «все срабатывания пишутся как Вошёл»

Если direction всегда `in` независимо от направления прохода — почти наверняка
датчик 2 (GPIO5) висит в воздухе без подтяжки и его пин никогда не фиксирует
переход 1→0, поэтому блок кода для `out` просто не выполняется. В `main.py` для
обоих пинов включена `Pin.PULL_UP`, и добавлен отладочный вывод состояний
датчиков в консоль — после прошивки проверьте по выводу, реагирует ли датчик 2
на разрыв луча вообще.
